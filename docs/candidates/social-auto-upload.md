# `dreammis/social-auto-upload` 定向审计

- 审计日期：2026-08-23
- 固定版本：`1c66b7db4b30585bbb40c58eb0aa572ffa3cce97`
- 上游：<https://github.com/dreammis/social-auto-upload>
- 结论：参考浏览器上传流程和测试样本；不作为默认 connector，不复用 Web 后端、Cookie 管理或私有签名路径。

## 为什么看它

它覆盖抖音、小红书等国内平台，使用 Playwright/Patchright 驱动创作者页面，和当前“先跑通两个平台”的目标直接相关。相比只列项目名，固定 commit 做静态审计更能回答哪些代码可借、哪些不能进产品。

## 看到的实现

### 抖音

- 浏览器进入创作者发布页；
- 扫码登录并持久化 `storage_state`；
- 上传媒体，填写标题/正文，选择可见性等页面字段；
- 通过 selector 找到发布按钮并点击；
- 浏览器启动参数包含降低自动化特征的配置。

### 小红书

- 旧路径依赖网页 Cookie，例如 `a1`、`web_session`；
- 使用浏览器侧生成的私有签名，或依赖签名服务；
- 通过创作者页面 selector 上传和填写内容。

### 测试

仓库有参数校验、selector 和 mock 测试。这能帮助建立本机 smoke test，但不能证明平台页面在真实账号、验证码、审核和风控变化下长期稳定。

## 可组件复用

1. 媒体文件前置校验思路；
2. 按平台拆分上传步骤和错误分类；
3. selector mock/契约测试的组织方式；
4. 本机隔离浏览器 profile、扫码登录和非 headless 人工观察的调试流程；
5. 页面变化时收集截图、HTML 片段和失败阶段的诊断思路。

这些内容也应只在官方 SDK/API 暂不可用、用户明确同意试跑时作为 fallback 参考。

## 明确不复用

- Cookie 导出、集中保存或让 Agent 接触 Cookie；
- 小红书私有签名生成、远程签名服务或接口逆向；
- 降低自动化检测的规避手段；
- 无认证 Web 控制面；
- headless 定时发布和“点击按钮即成功”的回执模型；
- 把页面 selector 当成稳定平台契约。

## 安全与维护风险

[issue #214](https://github.com/dreammis/social-auto-upload/issues/214) 对仓库旧 Web 后端报告了无认证接口、Cookie 下载、CSRF/破坏性 GET、路径处理和依赖风险。这是公开 issue 的审计结论，不等于上游已确认所有问题，但足以阻止我们直接部署该 Web 后端或迁入真实登录态。

即使只取浏览器上传模块，也必须假设：

- 平台 DOM 随时变化；
- 登录态可能触发验证码或设备确认；
- “非商业使用”不等于平台允许自动化操作；
- 页面返回成功提示不一定等于内容公开可见；
- 浏览器 profile 包含敏感登录态，不能进入普通 DSH Settings、聊天、日志或 Git。

## 若作为 fallback，采用门是什么

只有以下条件同时满足才可做一次本机 smoke test：

1. 用户明确批准浏览器辅助路径；
2. 使用专门测试账号和可删除的测试内容；
3. 使用隔离、不可导出的本地 profile；
4. 浏览器可见运行，最终点击前停下由用户确认；
5. 不使用私有签名服务，不绕验证码或风控；
6. 用公开 URL、账号作品列表或人工查看验证结果；
7. 失败默认不自动重试发布。

## 与官方路径的关系

它不是抖音 OpenAPI 或两个平台 Share SDK 的替代品。当前优先级为：

```text
人工手机交接
  > 官方移动 Share SDK
  > 抖音获权后的服务器 OpenAPI
  > 用户明确批准的本机浏览器辅助 smoke test
```

浏览器项目的价值主要是提供失败样本和本机调试参考，而不是决定 Social Workbench 的架构。
